# Yuki Device Android

Android-клиент удалённого управления для экосистемы Yuki: foreground-сервис поддерживает
соединение с `yuki-core` и выполняет команды, присылаемые сервером (фонарик, громкость,
уведомления, открытие URL, ...), а небольшой интерфейс позволяет настроить соединение и выбрать,
какие команды разрешены.

## Требования

Android Studio, Kotlin, Gradle (wrapper включён в репозиторий - `./gradlew assembleDebug`).
Точные версии зависимостей (AGP, Kotlin, Compose BOM, ...) см. в `gradle/libs.versions.toml`.

## Конфигурация

Настраивается через интерфейс приложения: адрес сервера (`ws://host:port` или
`wss://host:port`), идентификатор устройства, токен аутентификации и список разрешённых команд -
в отличие от флажка в более ранних сборках, теперь этот список реально проверяется перед
выполнением команды, а не просто заявляется при рукопожатии `hello`. Настройки хранятся в
`SharedPreferences`; приложение не создаёт резервных копий своих данных
(`android:allowBackup="false"`), поэтому токен не попадает в `adb backup`/облачные резервные
копии.

`usesCleartextTraffic` по умолчанию остаётся включённым, поскольку транспорт по умолчанию во всей
экосистеме - незашифрованный `ws://`; если вы включите TLS на стороне `yuki-core`, имеет смысл
ужесточить это через `network_security_config.xml`, сделав TLS обязательным.

## Команды

Управление фонариком, громкостью, уведомлениями, яркостью экрана (только чтение), `open_browser`
(принимает только URL со схемой `http`/`https` - остальные схемы отклоняются, а не передаются в
произвольный `Intent`), и всё остальное, что есть в `CommandHandler.kt`.

## Протокол

Реализует Yuki Protocol `yuki/1.0` напрямую на Kotlin (`YukiMessage.kt`/`YukiProtocol.kt`), а не
встраивает копию из [`yuki-protocol`](../yuki-protocol) - при изменении протокола эту копию нужно
синхронизировать вручную.
